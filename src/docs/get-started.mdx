# Get started with @tedi-design-system/vue

### Installation

```bash
npm install @tedi-design-system/vue
```

The supported Vue version is **Vue 3.5 or newer** (`vue` is a peer dependency). Design tokens, fonts and icons come
from `@tedi-design-system/core`, which is installed with the package. See
[Supported versions](https://github.com/TEDI-Design-System/general/wiki/Supported-versions) for the support policy.

### Styles

Import the stylesheet once, at the entry point of your application. It holds the fonts, design tokens and the styles
of every component:

```ts
// main.ts
import { createApp } from 'vue';

import '@tedi-design-system/vue/index.css';

import App from './App.vue';

createApp(App).mount('#app');
```

Components do not import any CSS themselves, so the stylesheet is required.

### Importing components

Components are published as two separate entry points:

```ts
import { TediIcon } from '@tedi-design-system/vue/tedi';
import { TediCommunityComponent } from '@tedi-design-system/vue/community';
```

**TEDI-Ready** components are maintained by the TEDI team and meet the full
[Definition of Done](https://github.com/TEDI-Design-System/general/wiki/Definition-of-Done). **Community** components
are contributed and held to a lighter standard. Prefer a TEDI-Ready component where one exists.

Components are not registered globally: import them where you use them.

```vue
<script setup lang="ts">
import { TediIcon } from '@tedi-design-system/vue/tedi';
</script>

<template>
  <TediIcon name="home" />
  <TediIcon name="info" label="Information" color="brand" />
</template>
```

`class`, `style`, `id`, `aria-*` and `data-*` attributes fall through to the component's root element, so there are no
separate props for them.

### App settings

`createTedi` installs the app-level settings. It is optional: without it, components use the defaults (Estonian
texts, the `default` theme).

```ts
import { createTedi } from '@tedi-design-system/vue/tedi';

createApp(App)
  .use(createTedi({ locale: 'en', theme: 'dark' }))
  .mount('#app');
```

Options:

- `locale`: the language of the component texts (`et`, `en` or `ru`, a value or a ref, default `et`).
- `labels`: texts that override the built-in ones (see [Labels](?path=/docs/documentation-labels--docs)).
- `theme`: the theme (`default`, `dark` or a custom theme's name, a value or a ref, default `default`), see
  [Custom theming](?path=/docs/documentation-custom-theming--docs).
- `persist`: whether changes are saved in cookies (default `true`).

The settings live in the app (`provide`), not in module state, so every server-rendered request gets its own.

#### Persistence

When the language or theme changes in the browser, TEDI saves it in the `tedi-lang` or `tedi-theme` cookie for 30 days
(the same names and lifetime as the Angular library), renewed on every visit. Pass `persist: false` when the app
stores them itself. TEDI never reads the cookies itself: the app passes the saved values in as `locale` and `theme`,
which is what lets the server render the right language and theme. In a client-only app, read them from `document.cookie`:

```ts
const cookie = (name: string) => document.cookie.match(new RegExp(`(?:^|; )${name}=([\\w-]+)`))?.[1];

app.use(
  createTedi({
    locale: (cookie('tedi-lang') as TediLanguage | undefined) ?? 'et',
    theme: cookie('tedi-theme') ?? 'default',
  }),
);
```

### Nuxt

The library is SSR safe and works in Nuxt without a module. Add the stylesheet to `nuxt.config.ts` and import components
as above:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  css: ['@tedi-design-system/vue/index.css'],
});
```

Install `createTedi` from a plugin. `useCookie` reads the cookies from the request on the server and from
`document.cookie` in the browser, so both render the same language and theme:

```ts
// app/plugins/tedi.ts
import { createTedi, type TediLanguage, type TediTheme } from '@tedi-design-system/vue/tedi';

export default defineNuxtPlugin((nuxtApp) => {
  const lang = useCookie<TediLanguage | undefined>('tedi-lang');
  const theme = useCookie<TediTheme | undefined>('tedi-theme');
  nuxtApp.vueApp.use(createTedi({ locale: lang.value ?? 'et', theme: theme.value ?? 'default' }));
});
```

Render `<html lang>` and the theme class with `useHead`. `lang` lets screen readers pronounce the texts correctly; the
server cannot touch `<html>` otherwise, so without the class the page would flash the default theme until the client
applies the saved one:

```vue
<!-- app.vue -->
<script setup lang="ts">
import { useTediLabels, useTediTheme } from '@tedi-design-system/vue/tedi';

const { locale } = useTediLabels();
const { theme } = useTediTheme();
useHead({ htmlAttrs: { lang: locale, class: computed(() => `tedi-theme--${theme.value}`) } });
</script>
```

With `@nuxtjs/i18n`, pass its locale ref instead (see [Labels](?path=/docs/documentation-labels--docs)).

### Theming

TEDI applies the active theme as a `tedi-theme--<name>` class on the `<html>` element. `default` and `dark` ship with the
library's CSS; without a class, the `default` theme applies. Set the theme with the `theme` option of `createTedi` and
change it with `useTediTheme().setTheme`. See [Custom theming](?path=/docs/documentation-custom-theming--docs) for
switching at runtime and for custom themes generated from Figma.

### Icon fonts

`TediIcon` renders [Material Symbols](https://fonts.google.com/icons) in three styles (`outlined`, `rounded`, `sharp`),
each a separate font file of roughly 350–430 KB. `index.css` declares all three, so every style stays available. Use
**one icon style** throughout your application and load only that font:

```ts
// Everything except the icon fonts…
import '@tedi-design-system/vue/index-without-icons.css';
// …plus the one style you use (outlined is the TediIcon default).
import '@tedi-design-system/vue/icons/outlined.css';
```

Each import loads one font file:

- `@tedi-design-system/vue/icons/outlined.css`: `material-symbols-outlined.woff2`
- `@tedi-design-system/vue/icons/rounded.css`: `material-symbols-rounded.woff2`
- `@tedi-design-system/vue/icons/sharp.css`: `material-symbols-sharp.woff2`
- `@tedi-design-system/vue/icons/all.css`: all three

A `TediIcon` whose `type` has no imported style renders its ligature text instead of the glyph.

Browsers only download an icon font once a glyph uses it, so in a regular web app the unused styles cost nothing at
runtime. In a **PWA**, the service worker precaches every matching build asset, including fonts your CSS never
references. Exclude the unused styles from the precache, for example with `vite-plugin-pwa`:

```ts
VitePWA({
  workbox: {
    globPatterns: ['**/*.{js,css,html,woff2}'],
    globIgnores: ['**/material-symbols-{rounded,sharp}.woff2'],
  },
});
```

See the [core icons guide](https://github.com/TEDI-Design-System/core/blob/rc/docs/icons.md) for SCSS usage and custom
font paths.
