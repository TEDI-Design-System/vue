# Get started with @tedi-design-system/vue

### Installation

```bash
npm install @tedi-design-system/vue
```

The supported Vue version is **Vue 3.5 or newer** (`vue` is a peer dependency). Design tokens, fonts and icons come
from `@tedi-design-system/core`, which is installed with the package. See
[Supported versions](https://github.com/TEDI-Design-System/general/wiki/Supported-versions) for the support policy.

### Styles

Import the stylesheet once, at the entry point of your application. It holds the fonts, design tokens and the styles
of every component:

```ts
// main.ts
import { createApp } from 'vue';

import '@tedi-design-system/vue/index.css';

import App from './App.vue';

createApp(App).mount('#app');
```

Components do not import any CSS themselves, so the stylesheet is required.

### Importing components

Components are published as two separate entry points:

```ts
import { TediIcon } from '@tedi-design-system/vue/tedi';
import { TediCommunityComponent } from '@tedi-design-system/vue/community';
```

**TEDI-Ready** components are maintained by the TEDI team and meet the full
[Definition of Done](https://github.com/TEDI-Design-System/general/wiki/Definition-of-Done). **Community** components
are contributed and held to a lighter standard. Prefer a TEDI-Ready component where one exists.

Components are not registered globally: import them where you use them.

```vue
<script setup lang="ts">
import { TediIcon } from '@tedi-design-system/vue/tedi';
</script>

<template>
  <TediIcon name="home" />
  <TediIcon name="info" label="Information" color="brand" />
</template>
```

`class`, `style`, `id`, `aria-*` and `data-*` attributes fall through to the component's root element, so there are no
separate props for them.

### Nuxt

The library is SSR safe and works in Nuxt without a module. Add the stylesheet to `nuxt.config.ts` and import components
as above:

```ts
// nuxt.config.ts
export default defineNuxtConfig({
  css: ['@tedi-design-system/vue/index.css'],
});
```

### Theming

TEDI applies the active theme as a class on the `<html>` element. Only two themes ship with the library's CSS:

| Theme     | Class                 |
| --------- | --------------------- |
| `default` | `tedi-theme--default` |
| `dark`    | `tedi-theme--dark`    |

Without a class, the `default` theme applies. The library has no theme provider yet, so switch themes by setting the
class yourself:

```ts
document.documentElement.classList.remove('tedi-theme--default', 'tedi-theme--dark');
document.documentElement.classList.add('tedi-theme--dark');
```

In Nuxt, set it with `useHead({ htmlAttrs: { class: 'tedi-theme--dark' } })` so it is also rendered on the server.

Any other theme is a **custom theme and is not bundled**: generate it from your project's Figma variables with the
[TEDI Figma Variable Exporter plugin](https://www.figma.com/community/plugin/1612732083806730958), include the generated
CSS after the TEDI stylesheet and set its class. An unknown class fails silently: components keep rendering with the
default theme's values.

### Icon fonts

`TediIcon` renders [Material Symbols](https://fonts.google.com/icons) in three styles (`outlined`, `rounded`, `sharp`),
each a separate font file of roughly 350–430 KB. `index.css` declares all three, so every style stays available. Use
**one icon style** throughout your application and load only that font:

```ts
// Everything except the icon fonts…
import '@tedi-design-system/vue/index-without-icons.css';
// …plus the one style you use (outlined is the TediIcon default).
import '@tedi-design-system/vue/icons/outlined.css';
```

Each import loads one font file:

- `@tedi-design-system/vue/icons/outlined.css`: `material-symbols-outlined.woff2`
- `@tedi-design-system/vue/icons/rounded.css`: `material-symbols-rounded.woff2`
- `@tedi-design-system/vue/icons/sharp.css`: `material-symbols-sharp.woff2`
- `@tedi-design-system/vue/icons/all.css`: all three

A `TediIcon` whose `type` has no imported style renders its ligature text instead of the glyph.

Browsers only download an icon font once a glyph uses it, so in a regular web app the unused styles cost nothing at
runtime. In a **PWA**, the service worker precaches every matching build asset, including fonts your CSS never
references. Exclude the unused styles from the precache, for example with `vite-plugin-pwa`:

```ts
VitePWA({
  workbox: {
    globPatterns: ['**/*.{js,css,html,woff2}'],
    globIgnores: ['**/material-symbols-{rounded,sharp}.woff2'],
  },
});
```

See the [core icons guide](https://github.com/TEDI-Design-System/core/blob/rc/docs/icons.md) for SCSS usage and custom
font paths.
